# 需求与验收

## 设备与目标

- Keychron V1Z3，USB `3434:0311`，对应 `keychron/v1/ansi_encoder`，STM32L432。
- 键盘通过显示器 KVM 在主机间切换；不再每次拨动 Mac/Win 开关。
- 固件自身识别系统，不依赖各台电脑运行常驻程序。

## 已确认的规则

| 编号 | 需求 |
| --- | --- |
| R1 | 检测为 macOS 或 iOS：默认层 0（Mac）；Fn 层 1。 |
| R2 | 检测为 Windows 或 Linux：默认层 2（Win）；Fn 层 3。 |
| R3 | `OS_UNSURE` 或其他未处理值：保持当前默认层，不强制 Win。 |
| R4 | KVM USB 重新初始化后重新检测；使用 QMK 的复位和单次稳定结果选项。 |
| R5 | 保留实体开关；启动先使用开关状态，检测完成后自动选择，随后手动拨动可覆盖。 |
| R6 | 保留当前自定义键位、旋钮、VIA 改键和官方 11 个 Custom 项。 |
| R7 | OS 切层只更新运行时状态，不反复写 EEPROM。 |
| R8 | 保留只读诊断接口，能查看采用的 OS、最新猜测、默认层及运行时间。 |
| R9 | 升级前备份，刷机直连，读回校验，不写 OTP/选项字节、不解除读保护。 |

曾讨论“除 Apple 外包括未识别全部切 Win”，但用户最终选择 **R3 的保守规则先测试**，未实施强制 Win 兜底。

## 非目标与已知边界

- 不改 QMK 核心识别算法，不保证所有 KVM、USB hub、虚拟机环境识别正确。
- `OS_LINUX` 是 USB 请求特征分类，不是系统身份认证，也用于部分游戏机特征。
- 没有添加电脑端软件 DFU 命令，也没有新增默认 `QK_BOOT` 快捷键。
- 复现 Keychron 的快捷键序列，不保证系统仍提供 Siri/Launchpad/Cortana 对应功能。
- 不承诺复制全部原厂灯光细节；灯光配置可能因初始化恢复默认。

## 验收分层

1. **自动测试**：四种已识别系统之间 16 种切换、未识别保留两种基础层、实体开关、诊断；11 个 Custom 项及 Siri 时序；VIA JSON；全部键位和旋钮的 ELF 数据。
2. **设备校验**：DFU 固件读回一致；VIA 读回一致；版本正确；Mac 识别及默认层正确。
3. **人工实测**：按键/修饰键/Fn/旋钮、VIA 改键、Mac → Linux → Mac、Windows 双向切换、休眠唤醒、单台关机。

1.1.1 在刷写及设备校验后，用户反馈“完工”，视为用户确认当前场景可用；未逐项记录的休眠/关机/不同硬件测试仍不应标成已覆盖。
